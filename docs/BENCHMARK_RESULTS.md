# SenseVoice 全部引擎、精度及构建版本测试汇总

整理日期：2026-10-11。最新主对比为结果 10（baseline）与结果 9（aggressive），版本 0.4.0；历史结果 1～8 单独附表。

## 1. 范围与结论

- 最新测试包含 6 个引擎、27 个引擎／精度组合，每个组合都有 baseline 与 aggressive，共 **54 个实测配置**。模型目录为 24 个，sherpa 与直接 ORT 共享 3 个 ONNX 模型。
- **sherpa Q8** 是本次两个构建中最快的有效配置：baseline 486 ms，aggressive 574 ms，WER 均为 5.80%。
- **ncnn INT8** 的 aggressive 本次平均耗时减少 62.2%，加速 2.65 倍；历史上也有明显加速，但第 6、8 次没有持续复现。WER 历次均为 13.04%，高于 sherpa Q8、ORT Q8、MNN Q8、LiteRT Q8 和 GGUF Q8_0 的 5.80%。
- **低位量化主要带来模型体积收益，没有普遍提速**。ORT Q4、GGUF 的低位配置在本次均慢于各自 Q8。
- **LiteRT Q4、MNN Q6／Q4** 的模型包分别为 141.2、208.8、150.4 MB，WER 分别为 7.25%、4.35%、7.25%。MNN Q8 与 aggressive Q5 的测量存在大幅跳变。
- MNN Q2、ncnn FP16、LiteRT Q2 在两个构建均为空输出。ORT Q2、MNN Q3、GGUF Q3_K 的识别质量明显下降。
- 本文覆盖 4 线程实测配置；ncnn INT2／INT3、GGUF Q2_K／IQ1／IQ2 未纳入本次 APK。

## 3. 指标定义

- B：baseline；A：aggressive。耗时单位为毫秒，越低越好。
- **耗时减少率 = (B − A) / B × 100%**；正数表示 A 更快，负数表示 A 更慢。加速倍数为 B / A，与减少率不同。
- WER／CER：词／字符错误率，越低越好。本文统计对象为上述固定音频。
- 模型包 MB = modelBundleBytes / 1,000,000，包含报告所列模型与配套文件，不是 APK 大小。
- 峰值 PSS MiB = sampledPeakPssKb / 1024，统计应用进程总 PSS，采样间隔 100 ms。
- CV 为 10 次耗时的样本标准差／平均值。CV 越大，本轮耗时波动越大。
- 空输出表示本次识别文字为空，WER 为 100%；表格保留其耗时。

## 7. 量化含义与不可用组合

| 引擎 | 本次精度 | 量化范围 |
| --- | --- | --- |
| sherpa／ORT | Q8、Q4、Q2 | Q8 为官方动态量化模型；Q4／Q2 为常量 MatMul 权重 MatMulNBits，block 64。sherpa 与直接 ORT 共享模型文件。 |
| MNN | Q8～Q2 | 权重量化，block 64，浮点激活。 |
| ncnn | INT8、FP16 storage | 官方导出模型，INT8 为混合精度；FP16 指权重存储格式。 |
| LiteRT | Q8、Q4、Q2 | Q4／Q2 由原 W8 全连接权重再次量化；depthwise 权重仍为 W8，激活为 FP32。 |
| GGUF | Q8_0、Q6_K、Q5_0、Q5_K、Q4_0、Q4_1、Q4_K、Q3_K、FP16 | 模型内部为混合张量类型。 |

- **空输出**：MNN Q2、ncnn FP16、LiteRT Q2，B／A 都是 WER 100%。
- **严重退化**：sherpa Q2 WER 92.75%，ORT Q2 89.86%，MNN Q3 43.48%，GGUF Q3_K 23.19%。
- **未包含／无实测**：ncnn INT2／INT3；GGUF Q2_K、IQ1／IQ2 等。当前 GGUF 量化器对这些格式要求 importance matrix。

每个 GPU 行都保留同模型 CPU 对照；`ncnn`、`mnn`、`litert` 的既有 CPU 结果可直接作为对照。

运行方式：安装 APK，导入包含 GPU 文件的模型包，点击 **Run all imported**，导出 JSON，
然后在电脑上执行：

```powershell
python tools/check_gpu_results.py sensevoice-results.json
```

该脚本检查 GPU 行是否带 `backendInfo`、WER 是否超过 15%，并提示缺少 CPU 对照的组合。

后续补充实测数据时应沿用第 2 节的设备、线程、预热和重复设置，并记录 GPU 型号、
驱动版本、`loadMs`（含 shader/kernel 编译）与 `firstInferenceMs`。
